# GURUGURU - 個性AI対話・個性C生成サービス (v2)

自分の個性AI(個性A)を作り、他者の個性AI(個性B)と対話させ、そこから第三の人格「個性C」を育てていくローカルWebアプリ。

- PDF「記事へのレスコメント作成.pdf」で検討された **プロンプト版DROP**(Console / Memory / Belief / Emotion / Bias / Relationship Contextの6要素から、その場で必要なプロンプトを動的生成する仕組み)を実装
- note記事「個性C = A × B × 場 × 問い × 出来事 × 時間」の構想に基づき、対話後に **個性C**(痕跡・差分・未解決の問い・新しい問い)をタイムラインとして生成・蓄積
- 9/5 MTGの議論(「メモリ(記録)と記憶(感情の重みづけ)は違う」「反応テストテンプレートをMVPに」)を踏まえ、v2で以下を追加
  - **主観的感情メモリ**: 対話の各ターンで、発言と同時にその人物視点での感情・確信度・記憶文を生成。同じ対話でもA・Bで異なる記憶が残る
  - **関係スコア(信頼・距離・緊張・影響)**: 対話のたびにLLMが更新。相手からどう見えているかは非対称(A→BとB→Aで別々の数値)
  - **縁の地図**: 個性を中心にした関係グラフ。ノードで人物概要、線で関係スコア・双方の主観的記憶を確認できる
  - **反応テスト**: 「一番辛かった経験は?」等の定型問答集を実行し、個性の一貫性を検証できる
- v2.1: **個性Cと直接対話できる機能**を追加。個性Cは単一の一貫した人格ではなく、AとBの視点の間で**あえて結論を出さず揺れ続ける**存在として応答する
- v2.2: 課金(Stripe, ¥980/月)・月間利用上限(50回、超過分は¥500で+30回)・見本個性の削除保護を追加

## セットアップ

Python 3(標準のsqlite3を使用、追加DBインストール不要)+ Flask で動きます。

```bash
cd drop-app
pip3 install -r requirements.txt
cp .env.example .env
# .env を開いて ANTHROPIC_API_KEY にご自身のAPIキーを設定してください
python3 app.py
```

ブラウザで `http://localhost:3000` を開いてください。

## 使い方

1. **個性プロフィール** タブで、自分(個性A)と対話相手(個性B)のプロフィールを作成する
   - Console / Belief / Emotion / Bias は自由記述
   - Memory は「経験」と「その意味づけ」のペアを複数追加できる
2. **対話** タブで個性Aと個性Bを選び、問い(お題)とターン数を入れて「対話開始」
   - 交互に発言が生成され、吹き出し形式で表示される
   - 対話後、それぞれの Relationship Context に自動で記録される
   - 各発言には話者本人の主観的な感情タグ(例: trust・69%)が付く
3. 対話結果の下にある「この対話から個性Cを生成する」を押すと、個性Cのスナップショットが生成される
4. **個性C** タブで同じペアを選ぶと、これまでの個性Cスナップショットが時系列で見られる
   - 同じペアで対話を重ねるたびに、前回のスナップショットを踏まえて更新されていく(=「発酵」)
   - スナップショットが1件以上あるペアを選ぶと、下に**「個性Cと話す」**チャット欄が現れる。個性Cは「Aならこう言う、でもBはこう返す。私はまだ揺れている」という語り方で応答し、質問返しもしてくる。一貫したキャラクターは意図的に演じない
5. **縁の地図** タブで中心にする個性を選ぶと、対話したことのある相手が周りにノードとして表示される
   - ノードをクリック: その人物のプロフィールを表示
   - 線をクリック: 双方向の関係スコア(信頼・距離・緊張・影響)と、A側・B側それぞれの主観的記憶(感情タグ付き)を表示
6. **反応テスト** タブで個性を選び「テストを実行」を押すと、定型の質問(一番辛かった経験は?など)への回答が一覧表示される
   - チームで新しく作った個性が意図通りの人格になっているかを素早く確認する用途

## 制約 (v2)

- MVPは「プロンプト版」。Memoryの関連度選択は単純なキーワード一致(簡易版)
- 対話は同期実行、1リクエストにつき最大8往復まで。各ターンで応答+主観的メモリ+関係スコア差分を1回のAPI呼び出しにまとめて生成
- 認証・複数ユーザー対応なし(ローカル単独実行を想定)。関係データは全員で共有される単一DBなので、複数人で同時に触ると上書きし合う点に注意(9/5 MTGで共有されたプロトタイプと同じ制約)
- 縁の地図は固定の円形レイアウト(力学的なグラフ配置ではない)。関係ラベルは対話のお題から自動要約するか、`PUT /api/relationships/pair/<a>/<b>/label` で手動設定可能
- 次段階の候補: 家系図・関係者マップの自動生成、間接的な影響経路(Influence Path)のモデル化、関係スコアの時間経過による減衰
